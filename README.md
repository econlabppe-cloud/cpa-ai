# CPA-AI — הכנת ספרים ודוחות לעוסק מורשה

מערכת שקולטת חשבוניות, מסווגת אותן לפי כללי מס דטרמיניסטיים עם מקור משפטי לכל כלל,
ומכינה דוחות מע"מ, מקדמות והערכה שנתית. **המערכת מכינה — מייצג מורשה מאשר — השידור נעשה דרך המייצג.**

> כלי עזר בלבד, אינו ייעוץ מס. כללים שמסומנים "לא אומת" מכריחים בדיקה אנושית בכל מסמך שהם נוגעים בו.

## הרצה

```bash
cd cpa-ai
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m cpa_ai            # http://127.0.0.1:8000  (ממשק בעברית)
pytest                      # 276 בדיקות
```

תיעוד ה-API האינטראקטיבי: `http://127.0.0.1:8000/docs`

| משתנה סביבה | תפקיד |
|---|---|
| `CPA_AI_DATABASE_URL` | ברירת מחדל `sqlite:///./cpa_ai.db`. ל-PostgreSQL: `postgresql+psycopg://...` |
| `CPA_AI_API_KEY` | אם מוגדר — כל קריאה מחייבת כותרת `X-API-Key` |
| `OPENAI_API_KEY`, `CPA_AI_OPENAI_MODEL` | אופציונלי: חילוץ עם LLM (גם מתמונות). דורש `pip install openai` **והסכמת העסק** |
| `CPA_AI_HOST`, `CPA_AI_PORT` | כתובת השרת |

## חיבורים: איך חשבוניות מגיעות לבד

הרעיון: הלקוח לא מעלה כלום. חשבוניות ממייל וקבלות מוואטסאפ נקלטות, עוברות את אותם כללים, ורק מה שדורש עין אנושית מגיע אליו.

```
מייל (IMAP / webhook)  ─┐
WhatsApp (webhook)     ─┼─► ingest: אידמפוטנטיות → קריאת קובץ → חילוץ → דה-דופליקציה → כללי מס → שמירה
גרירה / הדבקה בממשק    ─┘                                                          └─► קובץ מקור נשמר
```

| ערוץ | איך מגדירים | מצב בדיקה |
|---|---|---|
| **גרירה, הדבקה, `.eml`** | עובד מיד בממשק | נבדק מקצה לקצה בדפדפן |
| **מייל — IMAP** (למשל Gmail) | `CPA_AI_IMAP_*` ב-`.env.example`; כתובת העסק `you+TOKEN@gmail.com` מופיעה בממשק | נבדק מול שרת IMAP מדומה. **לא נבדק מול Gmail אמיתי** (דורש סיסמת אפליקציה) |
| **מייל — ספק נכנס** | להפנות ל-`POST /api/v1/inbound/email` (גולמי) או `/api/v1/inbound/email/{token}/json` | נבדק עם הודעות שנבנו בבדיקות |
| **WhatsApp** | אפליקציית Meta + webhook ל-`/api/v1/inbound/whatsapp` (HTTPS ציבורי) + `CPA_AI_WHATSAPP_*` | נבדק מול Graph API מדומה בפורמט Meta (חתימה, מדיה, אידמפוטנטיות, תשובות). **לא נבדק מול Meta אמיתי** |
| **בנק** | ייבוא CSV בלשונית "בנק" | נבדק עם קבצים בקידוד UTF-8 ו-cp1255, הפרדת עמודות שונה |

> ⚠️ **תיבת מייל ייעודית.** חברו תיבה שמיועדת רק לחשבוניות (למשל כתובת חדשה בג'ימייל שאליה מועברות חשבוניות). `CPA_AI_IMAP_DEFAULT_BUSINESS` מכניס **כל** הודעה בתיבה לעסק, כולל מיילים אישיים. בלי ההגדרה הזו מעובדות רק הודעות שנשלחו לכתובת עם הטוקן (`you+TOKEN@...`). מיילים בלי חשבונית מזוהה (ניוזלטרים, לוגואים בחתימה) מדולגים.

**WhatsApp — צעדים (מתיעוד Meta, אומת חלקית ממקורות משניים):** ליצור אפליקציה ב-Meta for Developers עם WhatsApp; להגדיר Callback URL ל-`https://<הדומיין>/api/v1/inbound/whatsapp` ואת ה-Verify Token; להירשם לשדה `messages`; להעתיק את App Secret ואת טוקן הגישה ל-`.env`; בממשק, בבית, להזין את מספר הטלפון של הלקוח. הלקוח שולח תמונה או PDF של קבלה ומקבל תשובה בעברית. פקודות: **סטטוס**, **מה חסר**, **עזרה**. מגבלות Meta (חלון 24 שעות להודעות יוצאות, אישור עסק) חלות ולא נבדקו כאן.

**מה המערכת עושה בקליטה:**
- **אידמפוטנטיות:** שליחה חוזרת של אותה הודעה (Meta שולחת שוב אם אין תשובה מהירה) לא יוצרת מסמך ולא תשובה כפולים.
- **דה-דופליקציה בין ערוצים:** אותו קובץ, או אותו ספק + מספר מסמך + סכום, נקלט פעם אחת. זה מונע ניכוי מע"מ כפול. אותו ספק + תאריך + סכום בלי מספר מסמך נשמר אך מסומן "ייתכן כפילות" לבדיקה.
- **PDF דיגיטלי בעברית:** pypdf מחזיר עברית בסדר שונה לפי יוצר ה-PDF. המערכת מנסה כמה נורמליזציות ובוחרת לפי עקביות חשבונית (לפני מע"מ + מע"מ = סה"כ). כשאין עקביות מלאה המסמך עובר לבדיקה. PDF סרוק או תמונה נשמרים להזנה ידנית (או חילוץ בתמונה בהסכמת העסק).
- **קובץ מקור נשמר** לפי hash (חובת שמירת מסמכי מקור) וניתן להורדה ממסך המסמכים.
- **זיכרון ספקים:** כשמתקנים קטגוריה, היא חוזרת אוטומטית באותו ספק. אפשר לראות ולמחוק ב"עוד".

**בנק:** ייבוא CSV, התאמה לפי סכום + חלון תאריכים + שם ספק. התאמה עמומה לא נעשית אוטומטית. מראה "חיובים בלי קבלה" (מעל 30 ₪) ו"חשבוניות בלי תשלום".

## ארכיטקטורה

```
[טקסט / תמונה / קובץ]
        │
        ▼
[חילוץ] ── מחלץ מקומי (regex, ללא רשת)  |  OpenAI Structured Outputs (רק בהסכמה)
        │   הפלט: עובדות בלבד (ExtractedDocument). אין למודל שום החלטת מס.
        ▼
[מנוע כללים דטרמיניסטי] ── rules/data.py: נתונים מגורסים לפי תאריך + מקור משפטי + דגל verified
        │   מע"מ לפי תאריך · ספרת ביקורת ע.מ · מספר הקצאה · סיווג · שיעורי הכרה
        ▼
[בקרת איכות] ── ציון ביטחון, שגיאות חוסמות, כלל לא מאומת ⇒ תור בדיקה אנושית
        ▼
[הכנת דוח] ── מע"מ תקופתי · מקדמות · הערכה שנתית · קובץ מבנה אחיד (טיוטה)
        ▼
[אישור מייצג] ── רו"ח / יועץ מס / עו"ד + מספר רישיון + הצהרה; נחתם על hash של התוכן
        ▼
[שידור] ── לא ממומש במכוון (501). מורידים את הדוח המאושר ומגישים דרך המייצג.
```

### תיקונים לעומת תכנון המקור

1. **חוקי המס יצאו מה-LLM.** בתכנון המקור המודל קבע שיעורי הכרה ונימוק משפטי. כאן המודל רק מחלץ,
   ו`category_hint` שלו לא יכול לגבור על כלל (נבדק בטסט).
2. **מספר הקצאה (חשבוניות ישראל)** — חסר בתכנון המקור. הסף משתנה לפי תאריך המסמך:
   25,000 ₪ (5.5.2024) → 20,000 (2025) → 10,000 (1.2026) → **5,000 ₪ מ-1.6.2026**, לפני מע"מ.
   בלי מספר הקצאה המע"מ לא מנוכה, וההוצאה נרשמת כולל המע"מ.
3. **אין הגשה אוטונומית.** ייצוג מול רשות המסים מותר רק לרו"ח, יועץ מס או עו"ד. כל דוח עובר אישור מייצג;
   אם הנתונים השתנו אחרי ההכנה — האישור נדחה והדוח מסומן כמיושן.
4. **רישום תוכנה** הוא לפי נספח ה' להוראות ניהול פנקסי חשבונות ודורש הפקת קבצים במבנה אחיד.
   המודול קיים (`reports/unified_file.py`) אבל **פריסת השדות היא טיוטה** — חובה לתקף בסימולטור של רשות המסים.
5. **מספרי טפסים שלא אומתו (871, 1010) לא מקודדים.**
6. **תיקון 13 לחוק הגנת הפרטיות:** יומן ביקורת לכל פעולה, הסכמה מפורשת לפני העברה לספק LLM,
   ייצוא כל המידע של העסק, מחיקת טקסט גולמי (רשומות החשבונאות נשמרות בגלל חובת השמירה), אימות API.

## מה מאומת ומה לא

| נושא | מצב |
|---|---|
| מע"מ 18% מ-1.1.2025 (17% לפני כן) | אומת |
| ספי מספר הקצאה | **לא אומת** — מקורות משניים בלבד, סותרים במועדי המדרגות ובניסוח "מעל"/"ומעלה" |
| ספרת ביקורת ע.מ / ח.פ / ת.ז | אלגוריתם סטנדרטי |
| ציוד משרדי, תוכנה, מלאי, שירותים — 100%/100% | אומת |
| רכב 45% מס הכנסה, 2/3 מע"מ | **לא אומת** — תלוי בפרופיל השימוש; תמיד לבדיקה |
| כיבוד 80% / מע"מ 0% | **לא אומת** (שיעור המע"מ) |
| אירוח 0%/0% | **לא אומת** (חריג אורח מחו"ל לא ממומש) |
| מדרגות מס (הערכים בקוד) | **לא אומת** — הערכים תואמים לטבלה שדווחה לשנת 2026 במסמך כנסת; מקור אחר מדווח הקפאה. תיוג קודם "אומת" היה שגוי |
| מדרגות מס 2026 | **לא אומת** — דווח על הרחבה רטרואקטיבית של מדרגות 20% ו-31%; הקוד משתמש באותן מדרגות עם אזהרה בדוח |
| מבנה אחיד | **טיוטה** |

לעדכון כלל: עורכים את `cpa_ai/rules/data.py` בלבד, ומעדכנים `verified=True` רק אחרי אימות מול מקור רשמי.

## אבטחה ושלמות (סבב ביקורת 1–3)

- **אימות:** `CPA_AI_USERS='{"מפתח":"שם"}'` — מפתח אישי; השם ביומן נגזר מהמפתח ולא מכותרת שהלקוח שולח. בלי זה: מפתח משותף (`CPA_AI_API_KEY`) והשם מהכותרת.
- **השרת לא עולה בלי מפתח** (אלא `CPA_AI_ALLOW_INSECURE=1` לפיתוח מקומי בלבד).
- **יומן ביקורת מקושר בשרשרת hash:** שינוי או מחיקה ישירה במסד שוברים את השרשרת. בדיקה: `GET /api/v1/audit/verify`.
- **נעילת תקופה:** אחרי אישור מייצג אי אפשר להוסיף או לשנות מסמך בתאריך שבתוך התקופה. מסמך שנדחה לא ניתן לאישור.
- **מבנה אחיד:** קידוד ISO-8859-8 מחמיר. שם שמכיל תו שאינו ניתן לייצוג נכשל בשגיאה (לא מוחלף בשקט).
- **מחלץ מקומי:** חשבונית מס בלי פירוט לפני מע"מ ומע"מ לא מאושרת אוטומטית; סכומים עם רווח כמפריד אלפים נקראים נכון.

## שכבות נוספות: חוקיות, מודל מס, יועץ, אבטחה

**חוקיות ועמידה בדין (בקליטת מסמך):**
- **תשלום במזומן:** המערכת מזהה "שולם במזומן" ומתריעה מעל תקרה (6,000 ₪; מקורות סותרים מול 11,000) — קנס מדווח 15%–30%, פיצול עסקה נחשב הפרה. הסף **לא אומת**.
- **ספק זר / מטבע חוץ:** חשבונית ב-USD/EUR/GBP או מחברה זרה לא נכשלת על "חסר מספר עוסק". אין ניכוי מע"מ, ונדרש להזין סכום בש"ח לפני אישור. האם נדרשת חשבונית עצמית (ייבוא שירותים) — מקורות סותרים, מסומן לבדיקת המייצג.
- **סוג קובץ לפי תוכן:** `%PDF-`, JPEG/PNG/GIF/WEBP לפי magic bytes. HTML ו-SVG נשמרים כטקסט ומוגשים כ-`text/plain` בלבד. נסגרה פגיעות של XSS שמור: קובץ HTML שהועלה היה מוגש כדף ורץ בדומיין האפליקציה.

**מודל נטל מס אחד (`cpa_ai/tax_model.py`)** — משמש גם את ההערכה השנתית וגם את ה-what-if: מס הכנסה + ביטוח לאומי ומס בריאות (הכנסה מזערית, שתי מדרגות, תקרה, ניכוי 52%), הפסד מועבר, זיכוי תרומות (סעיף 46), לוח פחת לרכוש קבוע (קו ישר, יחסי לימים). כל פרמטר ב-`rules/data.py` עם מקור ודגל אימות. שנה בלי טבלה (תכנון לשנה הבאה) משתמשת בטבלה האחרונה הידועה ומסומנת כלא מאומתת.

**יועץ תכנון מס — מה נוסף:**
- **מה-אם:** `POST /api/v1/businesses/{id}/advisor/what-if` — פנסיה (ערוץ זיכוי מול ניכוי לפי השיעור השולי), קרן השתלמות, תרומה, רכישת ציוד (פחת יחסי + מע"מ מוחזר + דרישת מספר הקצאה), משרד בבית (יחס חדרים; אין כלל רשמי), הכנסה נוספת. כל תרחיש מציין אם הנתונים מאומתים.
- **תחזית שנתית:** באמצע השנה הרווח "עד היום" נמוך מהרווח השנתי, ולכן הוסף `projected_profit` ואזהרה עם הערכה לפי הקצב.
- **אסטרטגיות חדשות:** לוח פעולות לסוף השנה, בדיקת נקודות זיכוי (₪2,904 לנקודה), עוסק מורשה מול פטור, תשלומים במזומן, הוצאות מספקים זרים, הפסד מועבר. השוואת חברה מול עוסק כוללת עכשיו את ביטוח הלאומי של העצמאי.
- משימת "סוף שנת המס מתקרב" במסך הבית ב-60 הימים האחרונים.

**אבטחה:**
| שכבה | מימוש |
|---|---|
| **הרשאות לפי עסק ותפקיד** | `CPA_AI_USERS='{"k":{"name":"דנה","role":"client","businesses":[1]}}'`. תפקידים: `admin` (הכל), `accountant` (העסקים שלו + אישור והגשת דוחות), `client` (העסק שלו בלבד). שער אחד על כל בקשה — נקודה חדשה מוגנת אוטומטית. עסק שאינו שלך מחזיר 404 (לא מגלה שהוא קיים), והניסיון נרשם ביומן |
| **הגבלת קצב** | API 600/דקה לכל מפתח, קליטה חיצונית 120/דקה לכל IP, נעילה אחרי 20 ניסיונות מפתח כושלים ב-5 דקות. `X-Forwarded-For` מכובד רק עם `CPA_AI_TRUST_PROXY=1` |
| **כותרות אבטחה** | CSP עם nonce לכל בקשה (אין script מוטבע), `X-Frame-Options: DENY`, `nosniff`, `no-referrer`, `Cache-Control: no-store` ל-API, HSTS מאחורי HTTPS |
| **הצפנה במנוחה** | `CPA_AI_ENCRYPTION_KEY` (`python -m cpa_ai gen-key`). קבצי מקור מוצפנים ב-Fernet; כמה מפתחות מופרדים בפסיק מאפשרים רוטציה. **המסד עצמו אינו מוצפן** — להשתמש בהצפנת דיסק או ב-PostgreSQL עם הצפנה |
| **גיבוי ושחזור** | `python -m cpa_ai backup out.zip` / `verify-backup` / `restore`. snapshot עקבי של SQLite, manifest עם גיבוב לכל רכיב, המסד בתוך הגיבוי מוצפן אם הוגדר מפתח, שחזור מסרב לדרוס יעד קיים. PostgreSQL: `pg_dump` |

## מה עוד חסר לפני שימוש אמיתי

- **אימות כל הכללים שמסומנים "לא אומת" על ידי יועץ מס.** זה החסר הגדול ביותר: מדרגות מס, מספר הקצאה, תקרת מזומן, שיעורי פחת, ביטוח לאומי וניכוי 52%, תקרות פנסיה וקרן, תרומות, פטור. ראו `docs/research-log-2026-10.md`.
- **כסף כ-float:** החישובים מעוגלים בגבולות, אבל לדיוק חשבונאי צריך `Decimal` בכל המסלול.
- **מיגרציות:** מיגרציה קלה מוסיפה עמודות (`cpa_ai/migrate.py`), בלי Alembic. שינוי סוג, שם או מחיקה דורשים כלי ייעודי.
- **הגבלת הקצב בזיכרון:** מתאימה לתהליך בודד. מאחורי כמה תהליכים — להעביר לפרוקסי או ל-Redis.
- **OCR:** PDF סרוק ותמונות לא נקראים מקומית. נשמרים לתיקון ידני, או נקראים דרך LLM בהסכמת העסק.
- **מחלץ מקומי:** נבדק על מספר צורות חשבונית בלבד. חשבוניות באנגלית, מטבע מעורב ופורמטים חריגים — יש לבדוק על מסמכים אמיתיים.
- **ייבוא שירותים (חשבונית עצמית):** לא ממומש, רק מסומן.
- **ביטוח לאומי של בעלים בחברה** ומס יסף: לא מחושבים בהשוואת חברה/עוסק.
- **תיקוף קובץ המבנה האחיד** בסימולטור רשות המסים, ואימות מספרי הקצאה מול חשבוניות ישראל.
- **הסכם עיבוד נתונים (DPA)** עם ספק ה-LLM, אם משתמשים בו.
