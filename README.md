# CPA-AI — הכנת ספרים ודוחות לעוסק מורשה

מערכת שקולטת חשבוניות, מסווגת אותן לפי כללי מס דטרמיניסטיים עם מקור משפטי לכל כלל,
ומכינה דוחות מע"מ, מקדמות והערכה שנתית. **המערכת מכינה — מייצג מורשה מאשר — השידור נעשה דרך המייצג.**

> כלי עזר בלבד, אינו ייעוץ מס. כללים שמסומנים "לא אומת" מכריחים בדיקה אנושית בכל מסמך שהם נוגעים בו.

## הרצה

```bash
cd cpa-ai
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m cpa_ai            # http://127.0.0.1:8000  (ממשק בעברית)
pytest                      # 57 בדיקות
```

תיעוד ה-API האינטראקטיבי: `http://127.0.0.1:8000/docs`

| משתנה סביבה | תפקיד |
|---|---|
| `CPA_AI_DATABASE_URL` | ברירת מחדל `sqlite:///./cpa_ai.db`. ל-PostgreSQL: `postgresql+psycopg://...` |
| `CPA_AI_API_KEY` | אם מוגדר — כל קריאה מחייבת כותרת `X-API-Key` |
| `OPENAI_API_KEY`, `CPA_AI_OPENAI_MODEL` | אופציונלי: חילוץ עם LLM (גם מתמונות). דורש `pip install openai` **והסכמת העסק** |
| `CPA_AI_HOST`, `CPA_AI_PORT` | כתובת השרת |

## ארכיטקטורה

```
[טקסט / תמונה / קובץ]
        │
        ▼
[חילוץ] ── מחלץ מקומי (regex, ללא רשת)  |  OpenAI Structured Outputs (רק בהסכמה)
        │   הפלט: עובדות בלבד (ExtractedDocument). אין למודל שום החלטת מס.
        ▼
[מנוע כללים דטרמיניסטי] ── rules/data.py: נתונים מגורסים לפי תאריך + מקור משפטי + דגל verified
        │   מע"מ לפי תאריך · ספרת ביקורת ע.מ · מספר הקצאה · סיווג · שיעורי הכרה
        ▼
[בקרת איכות] ── ציון ביטחון, שגיאות חוסמות, כלל לא מאומת ⇒ תור בדיקה אנושית
        ▼
[הכנת דוח] ── מע"מ תקופתי · מקדמות · הערכה שנתית · קובץ מבנה אחיד (טיוטה)
        ▼
[אישור מייצג] ── רו"ח / יועץ מס / עו"ד + מספר רישיון + הצהרה; נחתם על hash של התוכן
        ▼
[שידור] ── לא ממומש במכוון (501). מורידים את הדוח המאושר ומגישים דרך המייצג.
```

### תיקונים לעומת תכנון המקור

1. **חוקי המס יצאו מה-LLM.** בתכנון המקור המודל קבע שיעורי הכרה ונימוק משפטי. כאן המודל רק מחלץ,
   ו`category_hint` שלו לא יכול לגבור על כלל (נבדק בטסט).
2. **מספר הקצאה (חשבוניות ישראל)** — חסר בתכנון המקור. הסף משתנה לפי תאריך המסמך:
   25,000 ₪ (5.5.2024) → 20,000 (2025) → 10,000 (1.2026) → **5,000 ₪ מ-1.6.2026**, לפני מע"מ.
   בלי מספר הקצאה המע"מ לא מנוכה, וההוצאה נרשמת כולל המע"מ.
3. **אין הגשה אוטונומית.** ייצוג מול רשות המסים מותר רק לרו"ח, יועץ מס או עו"ד. כל דוח עובר אישור מייצג;
   אם הנתונים השתנו אחרי ההכנה — האישור נדחה והדוח מסומן כמיושן.
4. **רישום תוכנה** הוא לפי נספח ה' להוראות ניהול פנקסי חשבונות ודורש הפקת קבצים במבנה אחיד.
   המודול קיים (`reports/unified_file.py`) אבל **פריסת השדות היא טיוטה** — חובה לתקף בסימולטור של רשות המסים.
5. **מספרי טפסים שלא אומתו (871, 1010) לא מקודדים.**
6. **תיקון 13 לחוק הגנת הפרטיות:** יומן ביקורת לכל פעולה, הסכמה מפורשת לפני העברה לספק LLM,
   ייצוא כל המידע של העסק, מחיקת טקסט גולמי (רשומות החשבונאות נשמרות בגלל חובת השמירה), אימות API.

## מה מאומת ומה לא

| נושא | מצב |
|---|---|
| מע"מ 18% מ-1.1.2025 (17% לפני כן) | אומת |
| ספי מספר הקצאה | **לא אומת** — מקורות משניים בלבד, סותרים במועדי המדרגות ובניסוח "מעל"/"ומעלה" |
| ספרת ביקורת ע.מ / ח.פ / ת.ז | אלגוריתם סטנדרטי |
| ציוד משרדי, תוכנה, מלאי, שירותים — 100%/100% | אומת |
| רכב 45% מס הכנסה, 2/3 מע"מ | **לא אומת** — תלוי בפרופיל השימוש; תמיד לבדיקה |
| כיבוד 80% / מע"מ 0% | **לא אומת** (שיעור המע"מ) |
| אירוח 0%/0% | **לא אומת** (חריג אורח מחו"ל לא ממומש) |
| מדרגות מס (הערכים בקוד) | **לא אומת** — הערכים תואמים לטבלה שדווחה לשנת 2026 במסמך כנסת; מקור אחר מדווח הקפאה. תיוג קודם "אומת" היה שגוי |
| מדרגות מס 2026 | **לא אומת** — דווח על הרחבה רטרואקטיבית של מדרגות 20% ו-31%; הקוד משתמש באותן מדרגות עם אזהרה בדוח |
| מבנה אחיד | **טיוטה** |

לעדכון כלל: עורכים את `cpa_ai/rules/data.py` בלבד, ומעדכנים `verified=True` רק אחרי אימות מול מקור רשמי.

## יועץ תכנון מס (`cpa_ai/advisor`)

מודול שמציע אופטימיזציה **לגיטימית בתוך החוק** על בסיס הנתונים של העסק:

| אסטרטגיה | מה מחשבים | מצב אימות |
|---|---|---|
| פנסיה לעצמאי (סעיפים 45א + 47) | מילוי הערוץ בעל הערך הגבוה קודם, בתקרות | דורש אימות |
| קרן השתלמות לעצמאי | ניכוי עד התקרה, לפי השיעור השולי | דורש אימות (נתון סותר) |
| מע"מ שנחסם בחוסר מספר הקצאה | סכום המע"מ החסום + פעולה: לבקש חשבונית מעודכנת | ערך מאומת, תקרה לא |
| בדיקת כלל הרכב | מע"מ שנוכה על רכב לבדיקה | דורש אימות |
| עוסק מורשה מול חברה | השוואה חלקית בלי ביטוח לאומי | דורש אימות — לא המלצה |
| הקטנת מקדמות (טופס 2216א') | עודף מקדמות מעל המס המשוער — **נזילות, לא חיסכון** | הטופס מאומת |

- `GET /api/v1/businesses/{id}/advisor?year=2026&existing_pension=...&existing_keren=...`
- רשימת "לא מוצע" נשלחת תמיד יחד עם הדו"ח.
- מקורות, סתירות ופערים: `docs/research-log-2026-10.md`.

## אבטחה ושלמות (סבב ביקורת 1–3)

- **אימות:** `CPA_AI_USERS='{"מפתח":"שם"}'` — מפתח אישי; השם ביומן נגזר מהמפתח ולא מכותרת שהלקוח שולח. בלי זה: מפתח משותף (`CPA_AI_API_KEY`) והשם מהכותרת.
- **השרת לא עולה בלי מפתח** (אלא `CPA_AI_ALLOW_INSECURE=1` לפיתוח מקומי בלבד).
- **יומן ביקורת מקושר בשרשרת hash:** שינוי או מחיקה ישירה במסד שוברים את השרשרת. בדיקה: `GET /api/v1/audit/verify`.
- **נעילת תקופה:** אחרי אישור מייצג אי אפשר להוסיף או לשנות מסמך בתאריך שבתוך התקופה. מסמך שנדחה לא ניתן לאישור.
- **מבנה אחיד:** קידוד ISO-8859-8 מחמיר. שם שמכיל תו שאינו ניתן לייצוג נכשל בשגיאה (לא מוחלף בשקט).
- **מחלץ מקומי:** חשבונית מס בלי פירוט לפני מע"מ ומע"מ לא מאושרת אוטומטית; סכומים עם רווח כמפריד אלפים נקראים נכון.

## מה עוד חסר לפני שימוש אמיתי

- **כסף כ-float:** החישובים עגולים בגבולות, אבל לדיוק חשבונאי צריך `Decimal` בכל המסלול.
- **מיגרציות:** אין Alembic. שינוי סכמה דורש מסד חדש. לפני פריסה אמיתית — להוסיף.
- **הגבלת קצב (rate limit)** ו-HTTPS מאחורי פרוקסי: לא ממומשים.
- **OCR ל-PDF:** לא ממומש (כרגע טקסט, או תמונה דרך LLM בהסכמה).
- **אימות טקסטים באנגלית ובפורמטים נוספים:** המחלץ המקומי נבדק על מספר צורות בלבד.

- אימות כל הכללים שמסומנים "לא אומת" על ידי יועץ מס (כולל מדרגות המס ומספר ההקצאה).
- תיקוף קובץ המבנה האחיד בסימולטור של רשות המסים, ואז הגשה לרישום התוכנה.
- אימות מספרי הקצאה מול ה-API של חשבוניות ישראל (כרגע נבדק רק מבנה).
- OCR מקומי ל-PDF (כרגע: טקסט, או תמונה דרך LLM בהסכמה).
- לוח פחת, ביטוח לאומי, ניכויי פנסיה/השתלמות, הפקת חשבוניות.
- הסכם עיבוד נתונים (DPA) עם ספק ה-LLM, הצפנה במנוחה, וניהול משתמשים והרשאות מלא.
